# Aqua Paradise — Blueprint страницы «Аттракционы и развлечения» (/attractions)

Статус: **концепция UI/UX утверждена**. Дата фиксации: 2026-10-26.
Этот документ описывает проектные решения; он не означает, что страница уже реализована.

## Назначение
- Единый каталог аттракционов и развлечений курорта на маршруте `/attractions`.
- Посетитель изучает развлечения всего острова, ищет по имени и фильтрует по интересам, тематической зоне, возрасту и росту.
- Каталог не должен напоминать типичный интернет-магазин: фотокарточки премиального тропического курорта в эстетике Tropical Luxury × Adventure.
- На `/zones` показываются только развлечения выбранной зоны, а `/attractions` содержит единый полный каталог.
- **Не создавать отдельную страницу для каждого аттракциона.** Подробности открываются в модальном окне поверх каталога.

## Внешний вид — вариант А «Фотокаталог»
- Вверху заголовок «Аттракционы и развлечения», короткий вступительный текст.
- Под заголовком: поиск и комбинированные фильтры над фотосеткой. Не боковая панель.
- Крупные фотографии, просторная типографика, аккуратная композиция, плавные последовательные появления карточек.
- Адаптивная сетка: несколько колонок на широком экране, меньше на планшете, одна на узком телефоне; точные breakpoint значения определить при реализации.
- Каждая карточка содержит **фото, название, тематическую зону, интенсивность, минимальный возраст и рост (когда применимы и подтверждены данными)**, краткую характеристику. Никаких придуманных лимитов.
- Hover/focus: деликатное выделение, без затрудняющих восприятие эффектов.

## Комбинированные фильтры — вариант В
Два уровня управления:
1. **Быстрые категории** (например, «Все», «Спокойные», «Семейные», «Экстрим»; окончательное соответствие категориям исходных данных проверяется перед реализацией).
2. **Точные фильтры**: тематическая зона, интенсивность (если не покрыта выбранной категорией), возраст посетителя, рост посетителя.

Правила:
- Можно комбинировать поиск, быстрые категории и точные фильтры; результат соответствует одновременно всем активным условиям.
- Рост и возраст оцениваются **совместно**; отсутствие ограничения не должно трактоваться как нулевое значение или выдуманный порог.
- Отбор по возрасту/росту — **предварительная подсказка, не гарантия допуска**: сопровождение взрослым, медицинские ограничения и иные правила проверяются отдельно.
- При отсутствии результата — понятное пустое состояние с предложением сбросить/изменить фильтры.
- Видимое количество найденных результатов, кнопка «Сбросить фильтры».
- Изменение параметров приводит к корректному обновлению результатов и списка «Показать ещё».

## Поиск по названию
- Поле поиска **над фильтрами**.
- Фильтрация по названию аттракциона в ходе ввода, без учёта регистра и крайних пробелов.
- Работает одновременно с активными фильтрами; не сбрасывает их самостоятельно.
- Пустой запрос показывает подходящие по остальным условиям развлечения.
- Нет совпадений — понятное сообщение и способ очистить поиск/фильтры.

## Карточка и модальное окно — вариант А
- Нажатие на фотокарточку открывает **крупное модальное окно** поверх текущего каталога.
- В окне: фотографии, название, зона, атмосферное описание, уровень интенсивности, подтверждённые ограничения по возрасту и росту, важные условия безопасности и иные фактические особенности.
- Крестик закрытия, клавиша Escape, корректное управление кнопкой «Назад»; при необходимости понятная ссылка на открытый аттракцион.
- **Глубокие ссылки на конкретное развлечение**, например `/attractions?ride=skyfall`; прямой переход открывает соответствующее окно. При закрытии URL обновляется без разрушения текущего пользовательского контекста.
- Возврат после закрытия к прежним фильтрам, результатам и позиции прокрутки.
- На телефонах окно практически полноэкранное, контент удобно прокручивается.
- Корректный фокус: перемещается в окно, удерживается в нём, после закрытия возвращается к инициировавшей карточке, если она ещё доступна.
- Не дублировать все характеристики в фотокарточках каталога: подробности — в окне.
- При реализации продумать доступность, фокус, history/back-forward, deep-link и отсутствие конфликтов с фильтрами.

## Большие каталоги — «Показать ещё»
- **Не использовать бесконечную прокрутку**.
- Первоначально **ориентир: 12 карточек**; при нажатии «Показать ещё» подгружается/открывается следующая порция без перезагрузки.
- Кнопка скрывается, когда все подходящие результаты отображены.
- Новые карточки добавляются после существующих без потери позиции чтения.
- При изменении фильтров/поиска количество отображаемых карточек приводится в соответствие новой выборке.

## Контент и границы
- Использовать проверенные сведения из `docs/website-requirements.md` и `docs/project-bible.md`.
- Включать не только горки, но и другие виды развлечений, если они определены документацией.
- Не придумывать новые аттракционы, ростовые/возрастные ограничения, расписания и технические характеристики.
- Если сведения между документами расходятся, выявлять расхождения и согласовать перед кодированием.
- Переходы из `/zones` могут передавать конкретный ride и открывать соответствующее окно каталога.

## Адаптивность, анимации и тесты
- Десктоп/планшет/смартфон, touch-навигация, keyboard/focus, доступные метки форм, контраст, reduced-motion.
- Последовательное появление фото и карточек без задержек, мешающих исследованию.
- Тесты: поиск с регистром и пробелами; комбинации быстрых и точных фильтров; возраст+рост; правила сопровождения; пустой результат; сброс; «Показать ещё»; открытие/закрытие модалки; direct-link; back-forward; сохранение прокрутки; мобильное окно; keyboard accessibility.

## Связи и документация
- `/zones` → `/attractions?ride=<slug>` из карточек выбранной зоны.
- `/attractions` не создаёт отдельные `/attractions/:slug` страницы.
- Этот blueprint нужно включить в итоговый Master Blueprint и синхронизировать с общим документом требований перед реализацией.
- После утверждения дизайна **каждой страницы** создаём её отдельный Blueprint в `docs/` и сохраняем в GitHub перед переходом к следующей.

## Оставшиеся детали для стадии реализации
- Финальные изображения и тексты по всем развлечениям, окончательная таксономия категорий и интенсивности.
- Точные размеры карточек, пороговые ширины адаптива, скорость анимаций.
- Проверка ограничений и неполных данных, единая модель данных с планировщиком.
