# Aqua Paradise — Hotel Page Blueprint (/hotel)

**Статус:** концепция страницы утверждена. **Дата фиксации:** 2026-10-26.  
**Тип:** UI/UX-спецификация будущей страницы, а не свидетельство готовой реализации.

## 1. Роль и визуальный язык
- Страница `/hotel` представляет пятизвёздочный **Paradise Grand Hotel & Villas** в составе Aqua Paradise Island Resort.
- Дизайн: **вариант А «Кинематографичный люкс»** — премиальная тропическая гостиничная эстетика, элегантная типографика, простор, большие фотографии, спокойные анимации. Менее динамично, чем аттракционы курорта.
- Композиция контента: **вариант Б «История + интерактивный каталог проживания»**.
- Страница информационно-демонстрационная. **Реальное бронирование номеров, проверка доступности и оплата не входят в MVP**. Не показывать фиктивную реальную доступность/сделанные бронирования.
- Отель — отдельный объект и страница, не одна из девяти тематических зон.

## 2. Разделы страницы
1. Кинематографичное вступление и знакомство с отелем.
2. Интерактивный каталог номеров и вилл.
3. «Отдых и впечатления» — асимметричная галерея.
4. «Рестораны и услуги» — два самостоятельных тематических блока.

## 3. Hero и знакомство с отелем
- Большая полноширинная панорама Paradise Grand Hotel, пальмы, курортная архитектура, бассейны, океан.
- Название **Paradise Grand Hotel & Villas** и элегантный короткий подзаголовок — поверх изображения с читаемой подложкой/контрастом.
- Лёгкое медленное движение/параллакс фона (если производительность позволяет), последовательное появление текста.
- Без повторения 1st-person водной горки/интро с главной, без долгой блокирующей заставки.
- После Hero — короткий атмосферный рассказ о гостинице и концепции пятизвёздочного тропического отдыха.

## 4. Интерактивный каталог проживания — вариант Б
- Верхняя навигация по группам проживания, примерные смысловые категории: **«Номера» / «Сьюты» / «Виллы»**. Это UI-группировка, **не новый утверждённый перечень тарифов или типов номера**.
- Для выбранного типа размещения: **слева крупная фотография (галерея фотографий)**, **справа название, описание и основные удобства**.
- Можно переключать изображения спальни, интерьера, террасы/вида, если для выбранного типа есть соответствующие ассеты. Переключение фотографий не меняет выбранный тип проживания.
- При выборе другого номера/виллы плавно обновляются фотография и содержание.
- На смартфоне: фотография сверху, далее название, краткое описание и характеристики.
- Никаких отдельных страниц для каждого номера в рамках утверждённой концепции; бронирования нет.

### Детали размещения — вариант Б «Краткий обзор + раскрытие подробностей»
- По умолчанию — атмосферное описание и несколько главных особенностей.
- Кнопка **«Все удобства»** разворачивает полный список доступных и подтверждённых характеристик **прямо внутри информационной колонки**, без модального окна и перехода.
- Повторное нажатие скрывает подробности. При смене типа размещения развёрнутый блок сворачивается.
- Подтверждённые параметры (например площадь, вместимость, комплектация) показывать только при наличии точных значений из требований. Не придумывать цифры или услуги.

### Категории из Project Bible (перечень предварительный)
Standard Room, Deluxe Room, Ocean View Room, Family Suite, Premium Suite, Ocean View Villa, Royal Paradise Villa.  
Точное оснащение, площади, вместимость и стоимость пока не согласованы. UI должен выдерживать изменение списка.

## 5. «Отдых и впечатления» — вариант Б «Галерея впечатлений»
- **Асимметричная фото-сетка** (например одна крупная вертикальная фотография + две меньшие), отличается от галереи номеров и больших секций Hero.
- Объекты гостиничного отдыха, подтверждённые документацией: например **Grand Infinity Pool**, озеленённые пространства и другие гостиничные зоны, не подменяя их зонами аквапарка.
- Выбор фотографии показывает краткое описание соответствующего пространства; выбранное фото деликатно выделяется.
- На мобильных — удобная вертикальная компоновка, без тесной мозаики.
- Мягкие staggered-анимации и учёт prefers-reduced-motion.
- Не придумывать пляж исключительно для гостиничных гостей, если соответствующий доступ не утверждён.

## 6. «Рестораны и услуги» — вариант А «Два тематических блока»
### «Гастрономия»
- Отдельный атмосферный блок с крупной фотографией гостиничного ресторана / ресторанной террасы и коротким вводным текстом.
- Использовать только подтверждённый гостиничный сервис (в Project Bible предусмотрены Paradise Dining, гостиничные рестораны/бары, обслуживание номеров).
- Не придумывать названия отдельных заведений, меню, цены или часы работы.

### «Услуги и комфорт»
- Более компактный информационный блок с тематическими группами, иконками и короткими описаниями вместо ещё одной большой фотогалереи.
- Подходящие направления из Project Bible: консьерж, круглосуточная регистрация, хранение багажа, **Grand Kids Club**, wellness/fitness, доступность, транспортная связь с Paradise Loop, охрана и поддержка гостей.
- Показывать реальные по концепции услуги, не выдумывать условия включения в номер.
- Сочетание большого атмосферного гастрономического блока и компактного блока сервисов должно разнообразить ритм страницы.

## 7. Связь с миром курорта, условия проживания
- Отель расположен на возвышенности в первой половине острова; согласовать изображения и расположение с будущим Master Map.
- Для связи с центральными зонами существует Paradise Loop, пешие маршруты и предварительно индивидуальный трансфер для некоторых категорий размещения.
- **Проживание не означает автоматический доступ ко всем платным услугам аквапарка.** Возможные пакеты из Project Bible (Room Only, Bed & Breakfast, Stay & Splash, Family Paradise Package, Premium Paradise Experience) имеют предварительный статус; не изображать их как действующие предложения с готовыми ценами/условиями.
- Использовать материалы `docs/project-bible.md` и `docs/website-requirements.md` как источники фактической информации.

## 8. Движение и доступность
- Мягкий последовательный reveal элементов, неспешный визуальный ритм, быстрое и понятное переключение категорий/изображений.
- Обязательны мобильная адаптация, touch, клавиатурная навигация, alt для фотографий, контраст поверх Hero, видимый focus и prefers-reduced-motion.
- Доступное управление переключателем категорий, галереями и «Все удобства».
- Никаких фальшивых доступных номеров или функций бронирования.

## 9. QA-проверки
- Hero на десктопе/мобильном, читаемость заголовков на разных фотографиях.
- Переключение категории номера; корректные характеристики и связанные с ней фотографии.
- Независимая смена фотографии внутри выбранного размещения.
- Раскрытие/закрытие «Все удобства» и автоматическое сворачивание при смене номера.
- Галерея отдыха: выбор/смена изображения, показ верного описания.
- Доступность контента и элементов с клавиатуры; reduced-motion; корректное отображение без фото или при медленной загрузке.
- Отсутствие выдуманных значений площадей, цен и условий бронирования.

## 10. Отложено до реализации
- Финальные тексты Hero, описание гостиницы, ассеты каждой категории размещения и услуг.
- Подтверждение точных характеристик помещений и перечня сервисов по требованиям.
- Типографика, анимационные длительности и размеры для отдельных экранов.
- Согласование возможного упоминания пакетов проживания без обещания реально доступного бронирования.

## 11. Документирование
- После завершения концепции каждой страницы сохранять отдельный Markdown Blueprint в `docs/` GitHub до начала следующей страницы.
- В конце объединить согласованные решения в Master Blueprint и синхронизировать исходные требования.
